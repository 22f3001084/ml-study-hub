  2. One way is like calculating the answer directly, very fast for small data, using 'LinearRegression'. The other is like walking downhill, taking many small steps to reduce error. This 'SGDRegressor' method is slower per step but great for huge datasets, even handling data in chunks.

The one-minute story

Think of it like this

You already know two ways to find the best straight line through some dots:

  1. Do the algebra once and write the answer down (the normal equation). Fast and exact, but the algebra gets heavy when the table has lots of columns.
  2. Walk downhill (gradient descent): start anywhere, take small steps that reduce the error, stop when it stops improving. Slower per answer, but it copes with huge data and can be fed a few rows at a time.

In scikit-learn these are two classes: LinearRegression (the algebra) and SGDRegressor (the walking). This week you learn what each does, the dials on the walking one (learning rate, tolerance, iterations), and the clever partial_fit trick for data too big to load all at once.

By the end of this week you can:

  • fit a line with LinearRegression and read coef_ and intercept_;
  • write batch gradient descent from scratch and see it match LinearRegression;
  • explain batch, stochastic and mini-batch gradient descent;
  • configure SGDRegressor: loss, penalty, alpha, max_iter, tol, learning_rate, eta0, power_t, early_stopping;
  • use partial_fit for incremental learning and know which models have it.

Words you need

Words you need
  • Epoch - one full pass over the training data.
  • Learning rate η\etaη (eta0) - the step size.
  • Learning schedule - a rule for shrinking η\etaη over time.
  • Tolerance tol - "stop if the loss has not improved by at least this much".
  • Batch / stochastic / mini-batch - using all / one / a few examples per gradient step.
  • Incremental (online) learning - updating a model as new data arrives, using partial_fit.
  • coef_, intercept_ - the learned slope(s) and intercept (attributes end in _).

Idea 1: LinearRegression, the algebra route

from sklearn.linear_model import LinearRegression
import numpy as np

X = np.array([[0], [1], [2.]]); y = np.array([1, 2, 2.])
lr = LinearRegression().fit(X, y)
print(lr.coef_, lr.intercept_)       # [0.5] 1.1666...
print(lr.predict([[3]]))              # [2.6667]

It reproduces the line y^=76+12x\hat y=\frac76+\frac12xy^​=67​+21​x you derived by hand in MLF week 3. Under the hood it solves min⁡∥Xw−y∥2\min\|X\mathbf w-\mathbf y\|^2min∥Xw−y∥2 using a singular value decomposition (more stable than literally inverting XTXX^TXXTX).

  • No hyperparameters to tune (just fit_intercept=True by default).
  • Cost grows very fast with the number of features (roughly cubic) but only linearly with the number of examples. With hundreds of thousands of features it becomes slow.
  • No feature scaling needed for the answer (scaling just changes the units of the coefficients).
  • Predictions are fast.

On a noisy line made from y=4+3x+noisey=4+3x+\text{noise}y=4+3x+noise (100 points) we got intercept_ = 4.222 and coef_ = [2.968]: close to the truth (4,3)(4,3)(4,3) but not exactly, because of the noise.

Idea 2: Gradient descent, written out

The cost is the mean squared error. For parameters w\mathbf ww (intercept included via a column of ones in XXX):

J(w)=1n∥Xw−y∥2,∇J=2nXT(Xw−y)J(\mathbf w)=\frac1n\|X\mathbf w-\mathbf y\|^2,\qquad\nabla J=\frac2nX^T(X\mathbf w-\mathbf y)J(w)=n1​∥Xw−y∥2,∇J=n2​XT(Xw−y)

and the update is w←w−η∇J\mathbf w\leftarrow\mathbf w-\eta\nabla Jw←w−η∇J (MLF week 7). In NumPy:

Xb = np.c_[np.ones(len(X)), X]          # add the column of ones
w = np.zeros(2); eta = 0.1
for _ in range(1000):
    w -= eta * (2 / len(Xb)) * Xb.T @ (Xb @ w - y)

On the noisy-line data, after 1000 steps this gives [4.222, 2.968]: exactly what LinearRegression found. Same destination, different route.

Feature scaling matters for GD. If one feature is 1000 times bigger than another, the cost surface is a long narrow valley and gradient descent zig-zags and crawls. With StandardScaler the valley is round and it goes straight down. (Also: η\etaη too big diverges, too small crawls.)

Idea 3: SGDRegressor

from sklearn.linear_model import SGDRegressor
sgd = SGDRegressor(max_iter=1000, tol=1e-5, penalty=None, eta0=0.1, random_state=42)
sgd.fit(X, y.ravel())
print(sgd.intercept_, sgd.coef_, sgd.n_iter_)

On our noisy line this gave intercept_ ≈ 4.31, coef_ ≈ 3.05 after n_iter_ = 17 epochs: near the exact answer, found by 17 passes of one-example-at-a-time updates.

The four learning-rate schedules (learning_rate=):

ValueRule

How to write them in code (a favourite question):

SGDRegressor(learning_rate="invscaling", eta0=0.01, power_t=0.25)
SGDRegressor(learning_rate="adaptive",   eta0=0.01)
SGDRegressor(learning_rate="constant",   eta0=0.05)
SGDClassifier(learning_rate="optimal")      # default for the classifier

(The argument is learning_rate, a string, plus eta0 for the number.)

When does it stop? SGD stops when the loss has failed to improve by more than tol for n_iter_no_change epochs in a row (this is the meaning of the tolerance), or when max_iter epochs have run, whichever is first. n_iter_ records how many epochs it actually used. A bigger tol stops earlier (less accurate); a smaller tol runs longer.

Scale first. SGD is sensitive to feature scales. Put a StandardScaler in front, in a pipeline.

Idea 4: Learning in instalments: partial_fit

If the data does not fit in memory (or arrives as a stream), feed it in chunks. partial_fit performs one pass over the batch you give it and keeps the learned weights, so you can call it again and again:

sg = SGDRegressor(random_state=0)
for X_chunk, y_chunk in data_in_batches():     # your own generator
    sg.partial_fit(X_chunk, y_chunk)

(Do not use fit in a loop: each fit forgets what came before.)

Estimators that offer partial_fit ("incremental learners"):

  • Yes: SGDRegressor, SGDClassifier, Perceptron, PassiveAggressive*, MultinomialNB, BernoulliNB, GaussianNB, MiniBatchKMeans, MLPClassifier, MLPRegressor, IncrementalPCA.
  • No: LinearRegression, LogisticRegression, Ridge, Lasso, SVC, decision trees, random forests, KNeighbors*.

(For SGDClassifier.partial_fit you must pass classes= on the first call.) Using the LinearRegression class is not possible for out-of-core learning; SGDRegressor is the standard answer.

Solved example: 1. One gradient-descent step by hand

Question. Data (x,y)=(0,1),(1,2),(2,2)(x,y)=(0,1),(1,2),(2,2)(x,y)=(0,1),(1,2),(2,2). Start from w=(w0,w1)=(0,0)\mathbf w=(w_0,w_1)=(0,0)w=(w0​,w1​)=(0,0) with η=0.1\eta=0.1η=0.1 and the MSE cost. Compute one batch gradient-descent step.

Solved example: 2. Reading n_iter_

Question. SGDRegressor(max_iter=1000, tol=1e-3).fit(X, y).n_iter_ returns 12. What does that tell you?

Solution. It stopped after 12 epochs, far below max_iter=1000: the loss stopped improving by more than tol for n_iter_no_change (default 5) epochs in a row. If it had returned 1000 it would mean it hit the iteration cap without converging (you would increase max_iter or scale the features).

Solved example: 3. Which learner for which job?

Question. (a) A table of 5000 rows and 10 features. (b) A stream of 50 million rows that cannot fit in memory. (c) You want the exact least-squares answer with no tuning. Which class?

Solution. (a) and (c): LinearRegression (small data, exact, no hyperparameters). (b): SGDRegressor with partial_fit, one chunk at a time, after scaling.

Your turn: 5. Compare the routes

Explain in two sentences when you would prefer SGDRegressor over LinearRegression.

Need a hint?

Think about size and memory.

Show the full solution

When there are very many examples (or they arrive in a stream), SGD can update from small chunks with partial_fit and never needs the whole data or a heavy matrix computation. LinearRegression is simpler and exact, so it is better for modest-sized tables.

Watch out - real exam trap
  • The keyword is learning_rate (string) with eta0; not lr, not alpha.
  • partial_fit in a loop, not fit.
  • The classifier's default schedule is 'optimal'; the regressor's is 'invscaling'.
  • SGD needs scaled features; LinearRegression does not.
  • tol is about loss improvement, not about the size of the weights.

Recap

Remember this
  • LinearRegression solves least squares directly: exact, no hyperparameters, slow for huge feature counts. coef_, intercept_.
  • Gradient descent: w←w−η2nXT(Xw−y)\mathbf w\leftarrow\mathbf w-\eta\frac2nX^T(X\mathbf w-\mathbf y)w←w−ηn2​XT(Xw−y); batch / stochastic / mini-batch. Scale features.
  • SGDRegressor dials: loss, penalty, alpha, max_iter (1000), tol (1e-3), learning_rate (constant/optimal/invscaling/adaptive), eta0, power_t, early_stopping.
  • partial_fit for incremental learning (SGD, Naive Bayes, MiniBatchKMeans, MLP); not for LinearRegression.
Formulas to keep
  • MSE cost J=1n∥Xw−y∥2J=\frac1n\|X\mathbf w-\mathbf y\|^2J=n1​∥Xw−y∥2; gradient 2nXT(Xw−y)\frac2nX^T(X\mathbf w-\mathbf y)n2​XT(Xw−y)
  • invscaling: η=eta0/tpower_t\eta=\texttt{eta0}/t^{\texttt{power\_t}}η=eta0/tpower_t; adaptive: divide by 5 when stalled; constant: η=eta0\eta=\texttt{eta0}η=eta0
  • SGDRegressor defaults: squared_error, l2, alpha=1e-4, max_iter=1000, tol=1e-3, invscaling, eta0=0.01, power_t=0.25
  • SGDClassifier defaults: hinge, learning_rate="optimal"
