The one-minute story

Think of it like this

A smoke alarm can fail in two opposite ways. It can stay silent in a real fire (terrible), or it can scream every time you make toast (annoying, and soon people ignore it). A good alarm balances both.

A binary classifier has the same two kinds of mistakes, and the number "% correct" hides the difference. Picture a disease that only 2 people in 100 have. A "classifier" that always says "healthy" is 98% correct and catches zero sick people: useless!

This week you learn to count the two kinds of mistakes in a small table (the confusion matrix), turn them into precision, recall and F1, slide the decision threshold to trade one for the other, and summarise the whole trade-off with the ROC curve and its area (AUC).

By the end of this week you can:

  • build and read a confusion matrix (TP, FP, FN, TN);
  • compute accuracy, precision, recall, specificity, F1 by hand and with sklearn;
  • explain why accuracy fails on imbalanced data and use a DummyClassifier baseline;
  • move the threshold using decision_function, and read the precision-recall and ROC curves;
  • get honest predictions with cross_val_predict.

Words you need

Words you need
  • Positive class - the class we care about finding (disease, fraud, spam). Not "good".
  • TP / TN - true positive / true negative: correct predictions.
  • FP (false alarm, "Type I") - predicted positive, actually negative.
  • FN (miss, "Type II") - predicted negative, actually positive.
  • Precision - of everything we called positive, how much was truly positive?
  • Recall (sensitivity, TPR) - of all the truly positive, how many did we catch?
  • Threshold - the score cut-off for calling something positive.

Idea 1: The confusion matrix

Predictions versus truth, counted in a 2×22\times22×2 table. In scikit-learn the layout is

(TNFPFNTP)rows = actual (0, 1), columns = predicted (0, 1)\begin{pmatrix}TN&FP\\FN&TP\end{pmatrix}\qquad\text{rows = actual (0, 1), columns = predicted (0, 1)}(TNFN​FPTP​)rows = actual (0, 1), columns = predicted (0, 1)
from sklearn.metrics import confusion_matrix
confusion_matrix(y_true, y_pred)
tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel()
The idea
accuracy=TP+TNTP+TN+FP+FNprecision=TPTP+FPrecall=TPTP+FN\text{accuracy}=\frac{TP+TN}{TP+TN+FP+FN}\qquad\text{precision}=\frac{TP}{TP+FP}\qquad\text{recall}=\frac{TP}{TP+FN}accuracy=TP+TN+FP+FNTP+TN​precision=TP+FPTP​recall=TP+FNTP​
specificity=TNTN+FPF1=2 P RP+R  (harmonic mean of precision and recall)\text{specificity}=\frac{TN}{TN+FP}\qquad F_1=\frac{2\,P\,R}{P+R}\ \ (\text{harmonic mean of precision and recall})specificity=TN+FPTN​F1​=P+R2PR​  (harmonic mean of precision and recall)
Think of it like this

Precision asks "when you shout fire, how often is there a fire?" (penalises false alarms). Recall asks "of all the fires, how many did you shout about?" (penalises misses). F1F_1F1​ is high only when both are high.

Solved example: 1. The metrics from a count

Question. A binary classifier is evaluated on 500 test samples. It labels 120 samples as positive; of those, 90 are truly positive. The test set contains 110 actual positives. Find the confusion matrix and all the metrics.

Solution.

  • Actual negatives =500−110=390=500-110=390=500−110=390, so TN=390−30=360TN=390-30=360TN=390−30=360.
(TNFPFNTP)=(360302090)\begin{pmatrix}TN&FP\\FN&TP\end{pmatrix}=\begin{pmatrix}360&30\\20&90\end{pmatrix}(TNFN​FPTP​)=(36020​3090​)
  • accuracy =90+360500=0.90=\frac{90+360}{500}=\mathbf{0.90}=50090+360​=0.90

Idea 2: Accuracy can lie

If 98% of the examples are negative, the "classifier" that always predicts negative has 98% accuracy and 0% recall. That is exactly what a DummyClassifier(strategy="most_frequent") does, and it is the baseline any real model must beat:

from sklearn.dummy import DummyClassifier
DummyClassifier(strategy="most_frequent").fit(X_train, y_train).score(X_test, y_test)

On the breast-cancer data (212 malignant out of 569; we take malignant as the positive class), the dummy scores 0.629 accuracy and 0.0 recall: a decent-looking number with no cancer ever found.

So for imbalanced data, do not report accuracy alone. Use precision, recall, F1F_1F1​, the PR curve, or AUC. Which to favour depends on the cost of each mistake:

  • Missing a cancer (FN) is far worse than a false alarm: favour high recall.
  • Marking a good email as spam (FP) is worse than seeing one spam: favour high precision.

Remember the stratify= option of train_test_split to keep the rare class represented in both parts.

Idea 3: A real classifier, step by step

from sklearn.linear_model import SGDClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

clf = make_pipeline(StandardScaler(), SGDClassifier(loss="log_loss", random_state=42))
clf.fit(X_train, y_train)
y_pred = clf.predict(X_test)
confusion_matrix(y_test, y_pred)

We got (143 test patients, 53 malignant):

[[85  5]       TN=85  FP=5
 [ 7 46]]      FN=7   TP=46
accuracy 0.916   precision 0.902   recall 0.868   F1 0.885   specificity 0.944

Of the 53 truly malignant cases, the model found 46 (recall 86.8%) and missed 7; of the 51 it flagged, 46 were right (precision 90.2%).

Honest predictions on training data: cross_val_predict. It returns, for each training example, the prediction made when that example was in the validation fold (so no peeking), and is the standard way to build a confusion matrix without touching the test set:

from sklearn.model_selection import cross_val_predict
y_cv = cross_val_predict(clf, X_train, y_train, cv=3)
confusion_matrix(y_train, y_cv)         # [[261   6] [ 10 149]]

(cross_val_score returns one score per fold; cross_val_predict returns one prediction per example. Do not confuse them.)

Idea 4: The threshold, and the precision-recall trade-off

predict internally compares the score (decision_function) to a threshold (0 for this model, which is probability 0.5). Move the threshold yourself:

scores = clf.decision_function(X_test)
y_pred_new = (scores > threshold)
ThresholdPrecisionRecall
−2-2−2 (lenient: flag more)0.8910.925
000 (default)0.9020.868
+2+2+2 (strict: flag fewer)0.9570.849

Raising the threshold raises precision and lowers recall; lowering it does the opposite. You can have a lot of one only by sacrificing some of the other.

  • precision_recall_curve(y, scores) returns precisions, recalls, thresholds. precisions and recalls have one more entry than thresholds. Plot precision against recall to see the whole trade-off.
  • ROC curve: roc_curve(y, scores) returns false-positive rate FPFP+TN\frac{FP}{FP+TN}FP+TNFP​ and true-positive rate (= recall) for every threshold. A useless model hugs the diagonal; a great one hugs the top-left corner. AUC (roc_auc_score) is the area under it: 0.5 = random guessing, 1.0 = perfect. Ours: 0.973.
  • Use the PR curve rather than ROC when the positive class is rare (ROC can look flattering because the many negatives make the FP rate small).

Idea 5: Other classifiers, same metrics

Everything above works for any binary classifier (SGDClassifier, LogisticRegression, SVC, trees...). classification_report(y, pred) prints precision, recall, F1F_1F1​ and support per class plus averages:

  • macro average: the plain mean over classes (all classes equal).
  • weighted average: weighted by class size.

Solved examples

Solved example: 1. Which metric?

Question. For each, which metric matters most? (a) a screening test for a serious but treatable disease; (b) a spam filter where users hate losing real mail; (c) a data set with 99% negatives.

Solution. (a) Recall (do not miss sick people). (b) Precision (do not call real mail spam). (c) Not accuracy: use precision/recall/F1F_1F1​ or PR-AUC.

Solved example: 2. The 98 / 2 trap

Question. 1000 patients, 20 have the disease. A model predicts everyone as healthy. Give its accuracy, precision and recall.

Solution. Correct on all 980 healthy: accuracy =9801000=98%=\frac{980}{1000}=\mathbf{98\%}=1000980​=98%. It never predicts positive, so TP=0TP=0TP=0: recall =020=0=\frac0{20}=\mathbf0=200​=0, and precision is undefined (00\frac0000​; scikit-learn returns 0 with a warning). A 98% accurate model that finds no one.

Solved example: 3. Effect of the threshold

Question. You lower the decision threshold. What happens to precision, recall, FP and FN?

Solution. More examples get called positive: recall rises (fewer misses, FN falls), FP rises, and precision usually falls.

Always sketch the 2×22\times22×2 table first, note scikit-learn's row = actual, column = predicted layout, and compute from it.

Watch out - real exam trap
  • scikit-learn's layout is [[TN, FP], [FN, TP]]. A hand-drawn table in the question may have a different layout: read the labels.
  • Precision's denominator is predicted positives (TP+FPTP+FPTP+FP); recall's is actual positives (TP+FNTP+FNTP+FN).
  • Accuracy is misleading on imbalanced data.
  • Raising the threshold: precision ↑\uparrow↑ (usually), recall ↓\downarrow↓.
  • precision_recall_curve thresholds are one shorter than precisions/recalls.
  • cross_val_predict ≠\neq= cross_val_score.

Quick quiz

Quick quiz

A model has TP=40, FP=10, FN=20, TN=130. Its recall is...

  • 0.80
  • 0.667
  • 0.50
  • 0.929
Recall = TP / (TP + FN) = 40 / 60 = 0.667. (Precision would be 40/50 = 0.8.)

On a data set with 98 percent negatives, a model that always predicts negative has recall...

  • 98 percent
  • 50 percent
  • 0
  • undefined
It never finds a positive, so TP = 0 and recall = 0, even though accuracy is 98 percent.

Raising the decision threshold of a classifier usually...

  • increases precision and decreases recall
  • increases both
  • decreases both
  • has no effect
Fewer examples are called positive: the ones left are more likely to be truly positive, but more positives are missed.

Recap

Remember this
  • Confusion matrix (sklearn): (TNFPFNTP)\begin{pmatrix}TN&FP\\FN&TP\end{pmatrix}(TNFN​FPTP​). Precision =TPTP+FP=\frac{TP}{TP+FP}=TP+FPTP​, recall =TPTP+FN=\frac{TP}{TP+FN}=TP+FNTP​, F1=2PRP+RF_1=\frac{2PR}{P+R}F1​=P+R2PR​.
  • Accuracy misleads on imbalanced data; compare with a DummyClassifier.
  • Threshold up ⇒\Rightarrow⇒ precision up, recall down. PR curve for rare positives; ROC/AUC (0.5 random, 1 perfect).
  • cross_val_predict →\to→ out-of-fold predictions; cross_val_score →\to→ per-fold scores.
Formulas to keep
  • accuracy =TP+TNn=\frac{TP+TN}{n}=nTP+TN​; precision =TPTP+FP=\frac{TP}{TP+FP}=TP+FPTP​; recall (TPR) =TPTP+FN=\frac{TP}{TP+FN}=TP+FNTP​; specificity =TNTN+FP=\frac{TN}{TN+FP}=TN+FPTN​; FPR =FPFP+TN=\frac{FP}{FP+TN}=FP+TNFP​
  • F1=2PRP+RF_1=\frac{2PR}{P+R}F1​=P+R2PR​
  • confusion_matrix(y_true, y_pred) =[[TN,FP],[FN,TP]]=[[TN,FP],[FN,TP]]=[[TN,FP],[FN,TP]]
  • precision_recall_curve, roc_curve, roc_auc_score, classification_report
